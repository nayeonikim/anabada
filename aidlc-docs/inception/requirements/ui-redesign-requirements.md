## 3. 기능 요구사항 (Functional Requirements)

### FR-1. 검색 홈 화면 (Screen 1)
- 좌상단 브랜드 **"Anabada"**, 우상단 계정 칩 **"DevRel ▾"**(장식/표시용, 목업 유사).
- 중앙: 상단 라벨 "AI Knowledge Assistant", 대형 제목 **"무엇을 찾고 계신가요?"**, 서브 카피 "사내의 모든 지식에서 가장 적합한 답을 찾아드립니다."
- 중앙 **둥근 pill 검색바**(플레이스홀더 "업무와 관련된 질문을 입력하세요…") + 우측 원형 화살표 제출 버튼.
- **예시 질문 칩 3개**(목업 문구): "TDDI 신규 프로젝트에 적합한 사례를 찾아줘" / "중국 고객 프로젝트의 품질 이슈 사례가 있을까?" / "이전 유사 프로젝트의 일정을 알려줘". 클릭 시 검색바에 채워지거나 즉시 제출.
- 좌하단 **파스텔 그라데이션 장식**, 하단 중앙 푸터 **"Your Knowledge, Smarter with AI."**

### FR-2. 검색 제출 & 자동 분석 흐름
- 검색 제출 → 결과 화면으로 전환하며 **`/intent` 자동 호출 → 성공 시 `/advise` 자동 연속 호출**.
- 구조화된 의도(role/goal/function/data/output) **편집 화면 미노출**(내부 상태로만 보관).
- `/intent`가 **clarification**을 반환하면 진행을 멈추고 **추가 질문 UI**를 노출, 사용자 응답 후 재개.
- `/advise` context의 `role`은 기본값 **DevRel**(비노출), `userId`는 데모 기본값.

### FR-3. AI 진행 스텝바 (신규 컴포넌트)
- 헤더 "AI가 검토하고 있습니다…" + 4단계: **질문 이해 → 자료 탐색 → 후보 분석 → 판단 생성**.
- 단계 매핑: `/intent` 완료 = 1·2단계 완료 표시, `/advise` 진행 중 = 3단계 활성 + 진행률 **90% 유지**, 응답 도착 = 4단계 완료 + **100%** 후 결과 노출.
- % 는 부드러운 애니메이션. 설명문 "Confluence, JIRA, 내부 자료를 분석하여 최적의 답을 찾고 있습니다."

### FR-4. 결과 화면 (Screen 2, 세로 흐름)
1. 상단 **"← 새 질문하기"**(홈 복귀) + "내 질문" 라벨 + 질문 텍스트 + 타임스탬프.
2. (분석 중) AI 진행 스텝바(FR-3).
3. **최종 판정 배너**: 대형 원형 체크 아이콘 + 판정 대형 텍스트(REUSE/EXTENSION/NEED REVIEW/DEVELOP, 색상=기존 팔레트) + 판정 태그(예 "기존 자산 재사용 추천") + 요약 문장 + **"AI 요약 답변"** 박스(overallRationale).
4. **추천 후보 Top N**("추천 후보 Top 5", 우측 "적합도 높은 순"): 순위 배지 + 이름 + 메타(소스/태그) + 판정 배지 + 퍼센트 + 펼침(∨).
5. 후보 카드 펼침 시 **탭 3개**(D6 매핑): 판단 근거 / 적합도 분석 / 참고 자료.

### FR-5. 피드백
- 기존 `/feedback` 흐름 유지(선택 후보에 대한 채택/반려 등). 결과 화면 내 자연스러운 위치에 배치. 제출 확인(confirmationId) 표시.

### FR-6. 화면 전환/상태
- 홈 ↔ 결과 화면은 React 상태로 전환(router 없음). "새 질문하기"로 홈 상태 초기화(입력·결과 리셋).

### FR-7. 브랜딩/카피
- 사용자 노출 앱명 **Anabada**, 목업 카피·예시 질문·푸터 태그라인 적용. 코드 식별자(package.json name 등)는 유지.

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **NFR-1 (테마/디자인)**: 라이트 테마 — 흰색/밝은 배경, 파스텔 그라데이션, 부드러운 그림자·둥근 모서리. 판정 색상 팔레트 유지(REUSE=초록, EXTEND=파랑, NEEDS REVIEW=앰버, DEVELOP=보라). CSS 커스텀 프로퍼티(디자인 토큰) 방식 유지.
- **NFR-2 (접근성)**: 기존 접근성 수준 유지/이관 — `:focus-visible` 포커스 아웃라인, `role`/`aria-*`, 상태 라이브 안내, 키보드 조작 가능한 카드/탭/칩. 판정 색상은 텍스트/아이콘과 병행(색상 단독 의존 금지).
- **NFR-3 (성능)**: 신규 의존성 최소화(router 미추가). Vite 빌드/타입체크(strict) 통과 유지.
- **NFR-4 (호환성/기술스택)**: React 18 + TS(strict) + Vite 유지. 백엔드 API 계약(`/intent`·`/advise`·`/feedback`) 및 DTO 불변.
- **NFR-5 (반응형)**: 데스크톱 전용(모바일 최적화 대상 아님).
- **NFR-6 (유지보수)**: 권한 컨텍스트 주입 지점을 SSO 확장 가능하도록 단일 지점으로 유지.

## 5. 재사용 vs 신규

**재사용**: 판정 배지 색상 시스템 + `badges.ts`, 후보/랭킹 데이터 구조, 백엔드 API 흐름, 접근성 처리, `api/*` 클라이언트·타입.
**신규/재작업**: 라이트 테마 토큰 전면 재설계, 검색 홈 화면, 상태 기반 2단계 전환, AI 진행 스텝바 컴포넌트, 대형 판정 배너 + AI 요약 박스, 카드 내 탭 UI, 자동 intent→advise 오케스트레이션(+ clarification 분기).

---

## 6. 범위 밖 (Out of Scope)

- 백엔드(U1) 로직/계약 변경, 실제 SSO 인증 연동, 모바일 전용 최적화, 다국어(i18n), 다크 테마 유지, 클라이언트 라우팅.

---

## 7. 핵심 요구사항 요약

기존 다크 3컬럼 대시보드를 **Anabada 라이트 검색형 2단계 UI**(홈 → 결과)로 전면 교체한다. 검색 제출 시 `/intent`→`/advise`를 자동 연속 호출하고(clarification만 노출), AI 진행 스텝바(90%→100%)로 진행을 표현하며, 대형 판정 배너·AI 요약·Top N 후보·카드 내 3탭 상세로 결과를 세로 흐름으로 제시한다. 백엔드·API·판정 색상·접근성은 재사용하고, 데스크톱 전용·상태 기반 전환·신규 의존성 최소화를 원칙으로 한다.
