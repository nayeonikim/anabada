# Developer Use Case

## Use Case 1 — Existing project feature development / improvement

### Business situation

A developer needs to add a new feature, improve an existing feature, fix a defect, or expand supported behavior in an existing project.

Examples:
- Improve performance of an existing feature
- Add a new feature
- Fix a discovered problem or bug
- Expand the support range of an existing feature

## Happy Path — Current workflow

1. A new requirement or improvement need is identified.
2. The developer clarifies the problem and desired outcome.
3. The developer understands the existing project structure and related code.
4. The developer searches related code, documentation, issues, PRs, and reusable assets.
5. The developer decides whether to reuse, extend, or build something new.
6. The developer implements the change.
7. The developer validates the result with tests and review.

## Reuse decision output

- REUSE
- EXTEND EXISTING
- DEVELOP
- NEEDS REVIEW

## Context useful for the decision

- User role
- Task / problem statement
- Existing project or repository
- Related modules or components
- Similar implementations
- Documentation
- Issues / PRs
- Constraints
- Desired outcome
